# Canonical portfolio equity design

## Purpose and boundary

Completed trades are useful for expectancy and Profit Factor, but they cannot form an investable equity curve: ETF trades overlap, while the event sequence assumes each completed return owns the whole account in turn. The canonical layer therefore models capital, cash, concurrent positions, turnover, and daily marks separately. It does not change signals, entries, exits, stops, maximum holding time, cost amount, universe eligibility, date window, qualification, ranking, or the 540-strategy grid.

The fixed model name is `canonical_equal_weight_active_v1`. Its outputs are hypothetical research results, not actual investor profit and not qualification gates.

## Capital and allocation rules

- Initial equity is USD 1,000.
- Long only; no leverage, borrowing, pyramiding, or duplicate symbol position.
- Fractional shares are allowed. Every valid active position generated by a strategy is included; there is no entry ranking or maximum-position parameter.
- Active positions target equal dollar weight. Rebalancing occurs only when membership changes, at the next tradable open.
- With no positions, all capital is cash and earns no interest.
- Adjusted OHLC uses the existing Yahoo Finance `auto_adjust=True` convention. Raw opens are used for decisions; forward-filled adjusted closes are used only to value an already-active position.

## Deterministic daily event order

1. Execute gap/open stop exits using the existing fill rule.
2. Recognize max-hold exits scheduled for the day. The existing rule executes these at the close, so their future close proceeds are not available at the open.
3. Add valid next-open entries, rejecting a duplicate symbol membership.
4. Rebalance all current members at the open if membership changed.
5. Execute intraday stop exits. Proceeds remain cash until the next tradable open.
6. Execute scheduled max-hold exits at their existing close price, then mark remaining positions to adjusted close.

This distinction in step 2 is necessary to preserve the existing close-timed max-hold rule without using future high, low, or close data for an open decision.

## Costs

The unchanged 0.2% round-trip convention is split into 0.1% per side. The portfolio charges 0.1% of every actual buy, sell, and rebalance dollar. The equal-weight solver includes buy/sell cost when determining the affordable target, so cash cannot become negative.

## Series and formulas

Each daily strategy row contains date, strategy key, equity, cash, invested value, gross exposure, active-position count, daily return, cumulative return, running peak, drawdown, transaction cost, and turnover.

`equity_t = cash_t + invested_value_t`

`drawdown_t = equity_t / max(1000, equity_1 ... equity_t) - 1`

Summary output covers return, volatility, Sharpe/Sortino/Calmar, drawdown episodes, ulcer index, CDaR, daily/weekly/monthly left-tail measures, exposure, positions, cash days, turnover, and cost. Sharpe and Sortino assume zero risk-free cash return and are diagnostic.

## Benchmark

SPY is downloaded in addition to eligible symbols but is benchmark-only unless the unchanged universe already makes it tradable. Its adjusted close is normalized to USD 1,000 at the portfolio panel start. Yahoo’s adjusted series is total-return-compatible where vendor adjustment is available, but the output deliberately describes this as an adjusted-close proxy rather than guaranteeing independently reconstructed dividends.

## Bounded outputs

- `backtest_portfolio_strategy_summary.csv`: one row per strategy.
- `backtest_portfolio_curve_manifest.json`: bounded curve index and embedded selected-strategy summaries.
- `backtest_benchmark_spy.json`: normalized SPY series.
- `backtest_portfolio_curves/<strategy_key>.json`: chart series for all Qualified strategies, the primary candidate, and separate diagnostic leaders.
- `backtest_portfolio_daily_returns.csv.gz`: date plus all 540 daily strategy returns.

Curve keys are deduplicated, ordered by deterministic production qualification rank, and capped at 100. The matrix is deterministic gzip CSV because the repository has no Parquet engine dependency; about 2,500 by 540 scalar aggregates is bounded and remains subject to the workflow’s 45 MiB file limit. Raw trade events are not published.

## Limitations

The model assumes fractional fills at observed adjusted prices and does not model market impact, order queueing, taxes, cash interest, broker constraints, or intraday path beyond the existing stop-fill convention. Forward-filled close marks are valuation-only. Same-day stops after an open rebalance can create cash drag until the next open. Metrics remain in-sample diagnostics and do not become risk gates in this change.

## Post-merge validation

Development uses deterministic fixtures, targeted integration and JavaScript tests, syntax/static checks, and browser fallback testing. It intentionally does not run the full ten-year workflow. After merge, run Backtest Only once and verify: 540 summary rows; the existing 42 Qualified keys and production leader are unchanged; curve count is at most 100; all reconciliation/no-borrowing invariants hold; SPY and selected curves share the intended dates; the compressed matrix stays below 45 MiB; and the static dashboard loads available curves.
