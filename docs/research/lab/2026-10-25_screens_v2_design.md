# 선별 필터 재구성 (v2): 실무 스크리닝 방식으로 — 2026-10-25

설계 메모입니다. 백테스트는 돌리지 않았습니다. 사용자 지적("선별 점수 필터가 제대로 안 된 것 같다. 실무자·퀀트가 쓰는 스크리닝으로 재구성하라")에 따라
Stage A(결정 77–78)의 선별 방식을 뜯어보고, 실무에서 널리 쓰는 틀로 다시 짰습니다. 등록(DECISIONS)과 실행은 사용자 검토 뒤에 합니다.

## 1. Stage A 선별이 왜 엉성했나

| 문제 | 내용 |
|---|---|
| 점수 하나로 줄 세움 | "소형주 우선", "대형주 우선", "배당수익률" 같은 **단일 팩터 기울기**를 그대로 선별 기준으로 썼습니다. 이건 스크리닝이 아니라 스타일 베팅이라, 기간마다 어떤 스타일이 이기느냐를 재는 꼴이 됐습니다(1993–2023 배당·소형, 2017–2023 대형). |
| 추세 조건이 없음 | 실무 스크리닝의 핵심은 "지금 상승 추세에 있는가"를 **여러 조건으로 동시에** 확인하는 것인데(이동평균 배열, 52주 고가 근접, 52주 저가 대비 상승폭), 그 틀이 없었습니다. |
| 모멘텀 계산이 학술형 | 12-1개월 단순 수익률만 썼습니다. 실무(IBD RS)는 최근 분기에 가중을 둡니다. |
| 거래량 신호가 약함 | 매집/분산(오른 날 vs 내린 날 거래대금), 돌파의 거래량 확인이 없었습니다. |
| 업종을 안 봄 | 주도 업종 여부는 실무 스크리닝의 기본인데 업종 정보가 없었습니다(CRSP SIC 코드로 가능). |
| 유동성 위생이 섞여 있음 | 주가·거래대금 하한이 "제외 필터"에 섞여, 전략 의미가 있는 제외와 구분되지 않았습니다. |
| 매매층과 안 맞음 | 선별은 월 1회 교체 전제인데, 매매층은 30% 트레일링으로 오래 들고 가는 방식이라 모멘텀류가 불리했습니다. |

## 2. 재구성: 실무자들이 쓰는 스크리닝 구조

실무 스크리닝은 대개 **위생 → 추세 템플릿(하드 필터) → 상대강도·거래량 순위 → 진입 타이밍**의 순서입니다. 그대로 옮겼습니다.

### 0단계 위생 (거래 가능성, 전략 의미 없음)
| 스크린 | 기준 | 출처 |
|---|---|---|
| 상장 기간 | 최근 12개월 가격 이력 90% 이상 | 신규 상장 제외(실무 공통) |
| 최소 주가 | ≥ $10 | IBD는 $15, Minervini는 $10 안팎 |
| 최소 거래대금 | 21일 평균 ≥ $2M (계좌 100만 원 포지션의 수백 배) | 실무 공통 |
| 유동성 하위 (Amihud) | |수익률| ÷ 거래대금 상위 20% 제외 | Amihud 2002 |
| 시총 하한 | ≥ $300M (소형주 범위는 이 값으로 조절) | 실무 공통 |

### 1단계 제외 (전략적 "지금은 사지 않음")
| 스크린 | 기준 | 출처 |
|---|---|---|
| **추세 템플릿 미충족** | 종가 > SMA50 > SMA150 > SMA200, SMA200이 1개월 전보다 위, 종가 ≥ 52주 저가 × 1.3, 종가 ≥ 52주 고가 × 0.75 중 하나라도 어긋나면 제외 | Minervini SEPA(2013), Weinstein 2단계 |
| 단기 과열 | 종가 > SMA50 × 1.25 | "쫓아 사지 않기" 실무 규칙 |
| 약한 업종 | 업종(2자리 SIC) 6-1개월 평균 수익률 하위 30% | IBD 업종 순위, Moskowitz & Grinblatt 1999 |
| 고유 변동성 상위 | SPY 대비 잔차 변동성(63일) 상위 20% | Ang 등 2006 |
| 복권형 급등 | 지난 21일 하루 ≥ 20% 상승 | Bali 등 2011 (유지) |
| 고점 대비 큰 하락 | 52주 고가 대비 −X% 이상 | 떨어지는 칼 (유지) |
| 12개월 하락 추세, 36개월 과열 | (유지) | |

### 2단계 선별 순위 (여러 점수의 평균 백분위 → 상위 K)
| 점수 | 계산 | 출처 |
|---|---|---|
| **상대강도 등급 (RS)** | 최근 3개월 수익률 40% + 그 전 세 분기 각 20% 가중 → 백분위 0–100 | IBD RS Rating 공개 공식 |
| **매집/분산 비율** | 3개월간 오른 날 거래대금 ÷ 내린 날 거래대금 | IBD Accumulation/Distribution |
| **업종 상대강도** | 업종 평균 6-1개월 수익률 | IBD 업종 순위 |
| **52주 고가 근접 × 거래량 확인** | (종가 ÷ 52주 고가) × (20일 ÷ 120일 거래대금, 최대 3배) | O'Neil 돌파 확인 |
| 모멘텀 매끄러움, 변동성 대비 모멘텀 | (유지) | Da 등 2014, Blitz |
| 스타일 기울기(소형·대형·배당·장기 반전·저변동성) | **선별 기준이 아니라 비교용**으로만 남김 (`STYLE_TILTS`) | |

### 3단계 진입 타이밍 (기존 블록)
N일 신고가 돌파 + 거래량 증가 확인, 켈트너·볼린저 돌파, 또는 "조건 없음". 눌림 뒤 재진입(50일선 터치) 블록은 다음에 추가 후보.

## 3. 프로필: 실무자들이 발표한 조합 그대로

조합을 사람이 쓰는 형태로 미리 묶어 두었습니다(`screens.PROFILES`). **프로필 하나가 시험 단위**이고, 바꿔 끼우는 것은 프로필·K·매매층입니다. 값은 발표된 기본값이며 백테스트 전에 고정했습니다.

| 프로필 | 위생 + 제외 | 선별 순위 | 상위 K |
|---|---|---|---|
| Minervini 추세 템플릿 | 추세 템플릿 미충족, 단기 과열 25% | RS 등급 | 50 |
| IBD/CANSLIM 가격·거래량 | 고점 대비 15% 이상 하락, 약한 업종 30% | RS + 매집/분산 + 52주 고가 × 거래량 | 50 |
| 질 좋은 모멘텀 | 복권형 급등, 고유 변동성 상위 20% | RS + 매끄러움 + 변동성 대비 모멘텀 | 50 |
| 주도 업종의 주도주 | 약한 업종 50%, 추세 템플릿 | 업종 RS + RS | 50 |
| 저변동성 모멘텀 | 고유 변동성 상위 30% | RS + 저변동성 | 50 |
| 추세 템플릿만 | 추세 템플릿 | 없음(순위 없이 거래대금 순) | 전체 |

위생 5개는 모든 프로필에 공통으로 들어갑니다(상장 12개월, 주가 $10, 거래대금 $2M, Amihud 상위 20% 제외).

## 4. 매매층도 선별에 맞춰야 한다

Stage A는 매매층을 "30% 트레일링 + ATR 손절 3"으로 고정했는데, 월 1회 선별과 어긋났습니다. 다음 시험에서는 매매층을 두 가지로 둡니다.
- **교체형**: 매월 목록에서 빠진 종목을 다음 시가에 판다(새 청산 블록 "선별 이탈"). 모멘텀·RS 선별의 원래 쓰임새.
- **보유형**: 지금처럼 트레일링·ATR 손절로 들고 간다.
그리고 위험 기준 크기·열 상한·손익분기·부분 익절(결정 72–73)을 Sobol 변수로 둡니다.

## 5. 아직 못 넣은 것 (재무 데이터 필요)

CANSLIM의 C·A(분기·연간 이익 성장), Minervini의 이익 가속, Greenblatt의 EBIT/EV·ROIC, Piotroski F-score, P/E·P/B 같은 밸류에이션은 Compustat이 있어야 합니다. WRDS에서 `comp.funda`(연간)·`comp.fundq`(분기)와 CRSP-Compustat 링크(`crsp.ccmxpf_linktable`)를 받아 드라이브에 올려 주시면 같은 틀(위생·제외·순위)에 재무 스크린을 추가합니다. 필요한 항목: gvkey, datadate, fyear/fyearq, ib/ibq(순이익), epspx/epspxq, sale/saleq, at, ceq, oiadp, dltt, dlc, che, csho, prcc_f.

## 6. 구현 상태

- `lab/screens.py`: 위생 5종(`HYGIENE_SCREENS`), 제외 4종 추가(추세 템플릿, 단기 과열, 약한 업종, 고유 변동성), 선별 4종 추가(RS 등급, 매집/분산, 업종 RS, 52주 고가 × 거래량), 프로필 6종(`PROFILES`). 스타일 기울기는 `STYLE_TILTS`로 분리.
- `lab/crsp.py`: 패널 `info`에 SIC 코드 추가(업종 스크린용). 상위 3,000 패널을 다시 만들어야 업종 스크린을 쓸 수 있습니다(연구실 컴퓨터에서 30분).
- 테스트: 추세 템플릿·RS·업종·매집 계산과 프로필 6종이 마스크로 변환되는지 확인.
- 실행기(`screen_study.py`)는 아직 Stage A 메뉴를 가리킵니다. 프로필 × K × 매매층 비교 실행기는 등록 뒤에 만듭니다.
